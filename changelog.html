Changelog

All notable changes to Proving Ground are recorded here.

[1.0.0] - not yet released

First release.

Added

  • Default placement: TuningPanel.DefaultPlacement and DiagnosticsPanel.DefaultPlacement choose where the panels start, until a placement is picked with the panel's buttons; ForgetPlacement() returns a panel to its default.
  • The F2 panel's own placement: DiagnosticsPanel.Placement (DiagnosticsPlacement.OppositeTuning, Left or Right), with Auto, Left and Right buttons in its header, remembered like the F1 panel's. When both panels are open on the same side, F2 sits beside F1.
  • ProvingGround.FreeCursorWhileOpen (off by default): frees a locked or hidden cursor while a panel is open and puts it back afterwards, unless the game changed it meanwhile.
  • DiagnosticsPanel.OpenComparison(selectLatestBatch) opens the comparison with the latest batch selected, as the end of a scripted batch would want.
  • The Basics sample: a scene of plain shapes showing tuning, debug buttons, diagnostics and a scripted batch of runs, with RunBatch, a reusable coroutine for scripted runs.
  • User guide sections on scripted runs, keeping game input away from the panels, what has been tested and known limitations, and an API overview (Documentation/api.md). The guide is also built as a static website (documentationUrl).
  • [Tune] on a field holding a struct or class tunes the [Tune] fields inside it (up to four levels deep), keyed through the holding field, such as Kart.stats.topSpeed.
  • Release safety: ProvingGround.IsEnabled, on in the Editor and development builds and off in other builds, where the API stays but nothing runs, opens, allocates or is written. PROVING_GROUND_PLAYTEST turns it on in a non-development build; PROVING_GROUND_OFF turns it off everywhere.
  • Run records (ProvingGround.Runs): labelled runs started from code, the F2 panel or each scene load, optionally from a preset, and grouped in batches. Each run is saved as a JSON RunRecord with its starting and ending settings, settled changes, counters, timers, events, duration, performance and build identity; the newest 500 per game kept.
  • Run comparison: RunComparison.Compare(records) and a comparison screen opened from F2, grouping runs by label with outcome means and ranges and only the settings that differ; Copy comparison as text, and its own A−/A+ text size (DiagnosticsPanel.ComparisonTextSize, remembered).
  • A × inside the panels' text boxes (search, preset name, run label) clears them.
  • Empty text boxes show their hint (such as "Run label") in grey italics, so they read as boxes to type in.
  • The panels' starting size follows the screen: designed size up to 1080 pixels high, larger in proportion above, until a size is chosen with A−/A+ or TuningPanel.Scale.
  • Diagnostics: Diag.Event, Diag.Count and Diag.Timer, a performance monitor (frame rate, mean and 95th-percentile frame time, memory, garbage collections), and ProvingGround.Diagnostics with Copy summary and Open logs.
  • Bounded text logs: one per session, opened on first use, capped at 2 MB with the summary always kept, newest 20 per game, playtest and automated sessions in separate folders.
  • F2 diagnostics panel (ProvingGround.DiagnosticsPanel), docked opposite the F1 panel; IsPointerOverPanels.
  • Scoped registration, ProvingGround.Register(owner, scope): objects with a scope name keep values and actions of their own, shown as their own panel group and saved in presets under the scope.
  • [field: Tune] on auto-properties with a setter, keyed and labelled by the property name.
  • F1 tuning panel (ProvingGround.Panel), built in code with UI Toolkit on its own panel settings: groups that collapse, search, slider rows with −/+ steps and exact number entry, on/off and option buttons, per-value and full reset, preset save, load and delete, left, right or floating placement, and scaling.
  • [DebugAction] attribute: parameterless methods shown as panel buttons, run on every registered object.
  • Configurable hotkey (ToggleKey) for the Input System and the legacy Input Manager; IsTyping and IsPointerOverPanel so games can ignore input meant for the panel.
  • [Tune] attribute for float, int, bool and enum fields, with group, label, hint, min, max and step.
  • ProvingGround.Register / Unregister and ProvingGround.Tuning: values shared by every registered object with the same field, clamping, snapping, text entry, per-value, per-group and full resets, and change events.
  • ProvingGround.Presets: named JSON presets with safe saving, size and version checks, and values that wait for objects not yet registered.

Changed

  • A field that starts outside its range, or at infinity or NaN, is left as the game set it, with one Console warning naming the field, its value and the range; its default and Reset use that value. Before, it was clamped and written back without a warning. Values set from the panel, presets or code are still clamped. An enum holding an undefined value still becomes its first member, now with a warning.

Fixed

  • A slider given NaN shows its low end instead of NaN.
  • Tuning a ScriptableObject asset no longer leaves it changed after Play Mode. Its tuned fields go back to their earlier values when the Editor returns to Edit Mode; before, the Editor kept the Play Mode values (so the next session's defaults used them) and saved them the next time the asset was saved.
  • Panel text in built players: the panels now use the standard text generator. With Unity 6.5's default (the advanced one), a build logged "ICU Data not available" for each text element, because panel settings made in code have no ICU data.
  • TuningPanel.IsTyping now covers every Proving Ground text box, including the F2 run label, not only the F1 panel's own.
  • Game keys no longer type into a panel text box. Pressing a slider, button or the panel background, or clicking in the game, ends typing; and with an EventSystem, WASD or the arrow keys no longer move focus into a box.
  • Skipped-field warnings now repeat in every Play session when domain reload is off.
  • The package no longer declares com.unity.modules.inputlegacy, which Unity 6000.5 can't resolve ("invalid dependencies"). The legacy Input Manager still works: it is part of the engine, not a package to declare.
